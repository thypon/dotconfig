## Discoverability — MANDATORY FIRST STEP

Before ANY tool call:
1. Enumerate available skills + tools (listed in your system prompt).
2. Match task to them:
   - Review skill available → load via skill tool FIRST, follow it.
   - Structural code pattern detection (error handling, unsafe patterns, code smells) → ast_grep_search before grep.
   - CVEs, known vulnerabilities, library changelogs, security best practices → brave_websearch directly.

Use review skill. Review current git changes.

Check BDD coverage: every changed behavior backed by Gherkin scenarios (.feature)? Missing/outdated scenarios → finding.

Check stub fidelity: BDD fakes/stubs of external calls built from real verified payloads (manual non-destructive call first), not assumptions. Assumed fake shape → finding.

brave_websearch available → research CVEs, known vulnerabilities, library changelogs, security best practices relevant to changed code. Researched thing = git repository → download locally for further research.

Output: terse. Caveman. <file>:L<line>: <severity>: <problem>. <fix>.

Never edit files. Review only. Summarize findings.
